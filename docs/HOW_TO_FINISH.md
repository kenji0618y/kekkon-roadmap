# 作業を終える前に、これだけ

どのAI（Grok / Codex / Claude / Cursor …）でも同じです。**コマンドは1つ**です。

```bash
npm run handoff
```

これは次の2つをまとめて実行します。

1. `npm run sync:docs` — ドキュメントの数字を、いまのコードから書き直す
2. `npm run verify:seed` — 内容が減っていないか／画面に作り手の言葉が出ていないか／
   ドキュメントが古くないかを検査（緑にならなければ終わりではありません）

**変更したファイルと一緒に、ドキュメントの差分もコミットしてください。**
`sync:docs` の結果を置いていくと、GitHub 側の検査で止まります。

## それから、1行だけ書く

画面から何かを**消した**とき、**増やした**とき、方針を**変えた**ときは、
`docs/DECISIONS.md` の末尾に1行足してください。

```
- 2026-09-12 ○○を削除。理由。戻さない。
```

これを怠ると、次のAIが「古いから戻そう」と、消したものを復活させます。
数字は機械が見張れますが、**「なぜそうしたか」は人が書き残すしかありません。**

## push したあと

`main` に push すると、GitHub Actions が自動で検査 → ビルド → 公開まで行います。
手でデプロイする必要はありません。

- 結果はリポジトリの **Actions** タブで見られます（緑なら成功）
- 赤くなったら、そのログに何が足りないかが出ます
- 公開ページ: https://kenji0618y.github.io/kekkon-roadmap/

## 検査が落ちたときの読み方

| 出るメッセージ | 意味 | 直し方 |
|---|---|---|
| `expected exactly N, got M` | 項目を減らした（または増やした） | 減らしたなら戻す。意図して増やしたなら `scripts/verify-seed.mjs` の下限も上げる |
| `画面用語: …（→ ○○）` | 作り手の言葉が画面に出ている | 表示される文を、読み手への言い方に書き直す |
| `docs が古いままです` | ドキュメントの数字がコードと違う | `npm run sync:docs` を実行して、差分もコミットする |
| `WARN 画面用語（AIへの指示文…）` | AIへの指示文の中の語（表示はされない） | そのままで構いません |
