# 毎年の見直し手順

このファイルは開発用のメモです。年に一度、内容が古くなっていないかを確かめるときの手順です。
アプリの「設定」タブにも、たたんだ状態で載っています。

対象は `src/data/` の各ファイルです。
最終確認日はコード内の `reviewedOn`（`src/data/catalog.ts`）に入っています。

---

## 1. 毎年見直す項目（民間のサービス）

民間の割引やポイントは、条件が毎年のように変わります。
`tasks.json` で `"review": "YYYY-MM-DD"` が付いている項目がそれです。

`npm run build` を実行すると、最終確認から15か月を過ぎた項目が一覧で警告に出ます。
ビルドは止まりません。**警告が出たら、その項目を順に見直してください。**

見直しかた:

1. その項目の `sources` にあるURLを、ブラウザで開く
2. 割引率・上限・対象・受付の期限が変わっていないか見る
3. 変わっていたら `money_in` / `money_out` / `faq` / `summary` を直す
4. 終わっていたら、その項目を消さずに「終了しました」と書き換える
   （消すと、友人が「前に見たあれは？」と探したときに何も残りません）
5. 確かめ終わったら `"review"` を今日の日付にする
6. `sources.json` の `checked` も同じ日付にする

**自動チェックが効かないサイト**があります。Amazon・トイザらス・三井住友カードは、
プログラムからのアクセスを断るので403が返ります。切れているわけではないので、
ブラウザで開いて目で確かめてください（`sources.json` の `note` にも書いてあります）。

## 2. 市・国の制度

- 広島市の公式ページ（妊婦支援・こども医療・保育料・産後ケア・三世代近居など）を見直す
- 国の制度（NISA・iDeCo・住宅ローン控除・住宅取得等資金の贈与・児童手当・
  出産育児一時金・育児休業給付）を、国税庁・厚生労働省・こども家庭庁・日本年金機構で確認する
- **金額が変わったときだけ** `money_in` / `money_out` / `miss` を直す。
  推測で埋めない。分からないものは「会社によります・要確認」と書く

`deadlines.json` の日付が決まっている締切は、年度が変わると全部ずれます。ここは必ず見てください。

## 3. 対象外リスト（exclude.json）を守る

`exclude.json` は「この二人には当てはまらないもの」の一覧です。
理由を書いて残してあるので、人に「もらえるらしいよ」と言われても揺れずに済みます。

とくに **結婚新生活支援事業** は、広島市では実施していません。
もらえる額として数えたり、項目のタイトルにしたりしないでください。

```bash
node -e "const d=require('./src/data/tasks.json');
if(d.some(t=>/結婚新生活/.test(t.title))) throw new Error('結婚新生活をタイトルに出さない');
console.log('OK', d.length)"
```

FAQ の中で「広島市では受けられません」と注意書きするのは問題ありません。

## 3-2. ふたりの練習帳

`practices.json`（52）・`talks.json`（16）・`agreements.json`（18）・`refs.json`（18）です。
制度と違って毎年変わるものではないので、見直しの頻度は低くて構いません。

守ってほしいのは次の3つです。

- **研究で分かったことと、専門家の提案は分けたまま**にする。`refs.json` の `kind` がその区別です。
  混ぜると「研究で証明された」と読めてしまいます
- **`limits`（限界・確認した範囲）を消さない。** どこまで確かめられたかを書いた欄です（空だと検査で落ちます）
- **性犯罪・性暴力（R15）と DV相談（R16）の窓口を外さない。**
  外すとビルドが止まります。話し合いを無理に進めない、という但し書きも一緒に残してください

行動を「ノルマ」「点数」「診断」として見せる書き方はしないでください。
選んだ数は操作の目安であって、二人の関係の点数ではありません。

## 4. 書き方の決まり

- すべての項目に `why`（なぜやるのか）・`miss`（やらないと失うもの）・`window`（いつやるか）を入れる
- `steps` は3つ以上。`faq` は **新しく足す項目の目安として4組以上**。
  既存のうち15件（B13・W1〜W7・S1〜S4・P1〜P4）は出典が薄いため2〜3組のままです。
  **数をそろえるために推測で書き足さないでください。**（検査は合計数だけを見ています）
- `pad` は絵の上に出る短い名前。3〜8文字。長いと2行に折り返して収まらなくなる
- **画面に出る文章に、作り手あてのメモを書かない。**
  「〜は書かない」「〜するな」「賞品」「一次」「既定」といった言葉は、
  そのまま友人の画面に出ます。読み手への言葉で書いてください
- 金額は、公式ページに書かれている数字か、二人が自分で入力した記録だけを使う

---

## 5. 内容が減っていないかの検査

`npm run build` が `scripts/verify-seed.mjs` を先に走らせます。
項目数・FAQ の数・画面の部品が減るとビルドが止まります。

**内容を増やしたときは、この検査の下限も一緒に上げてください。**
上げ忘れると、次に誰かが減らしても気づけません。

---

## 6. 反映

直したら `npm run build` を実行し、`dist` を `gh-pages` ブランチに置きます。
`.nojekyll` を消さないでください。
Service Worker が古い画面を出すことがあるので、確認するときは強制リロードしてください。
